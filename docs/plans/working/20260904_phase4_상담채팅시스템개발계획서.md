# Phase 4: 실시간 채팅 — 완료

작성일: 2026-09-04 · 구현 검토 완료일: 2026-09-18

상태: **구현·로컬 통합 검증 완료**. 중단 전 수정 커밋 `13a00dc`를 이어받아 Phase5·6과 함께 회귀 검증했다. 공개 서비스 배포 완료를 뜻하지 않는다.

[검토 전 계획서](../history/20260918_phase4-6_review/20260904_phase4_상담채팅시스템개발계획서.md)는 원문 그대로 보존한다. 예전 예시 코드보다 이 문서와 실제 소스가 우선한다.

## Task 1: 연결 및 인증 — 완료

- [x] Express HTTP 서버에 Socket.IO 연결. Origin 허용 목록을 WebSocket handshake에도 적용.
- [x] 고객 자격(roomId/visitorToken)이 있으면 운영자 쿠키보다 우선하며, 일부만 있거나 잘못되면 운영자로 승격하지 않고 거절.
- [x] 잘못 인코딩된 쿠키·DB 인증 오류를 연결 실패로 처리.
- [x] 운영자는 쿠키 또는 명시적 테스트 토큰으로 인증. 활성 여부 및 토큰 유효성을 수신 이벤트와 메시지 방송 시 재검사.
- [x] 고객은 자신의 방만 접근. 고객용/운영자용 DTO 분리.

인증 시 한 번만 검사한다는 초안은 수정했다. JWT 자체를 서버에서 폐기하는 세션 저장소는 없으며, 클라이언트 로그아웃은 해당 앱 소켓을 닫는다. 다중 서버용 인증·어댑터·세션 폐기는 후속 범위다.

## Task 2: 메시지 및 입력 표시 — 완료

- [x] 저장은 `createMessageRow` 하나로 통합. `createMessageResult`는 같은 방 잠금 안에서 신규 저장 여부를 함께 반환한다.
- [x] 방별 clientMessageId 중복 방지와 다른 발신자의 ID 충돌 검사.
- [x] 성공 ack 및 실패 clientMessageId 전달. 고객은 8초 확인 실패/연결 해제 시 재시도 가능 상태로 전환.
- [x] 소켓 전송에도 사용자별 속도 제한 적용. 기본 60회/분, 같은 고객의 여러 연결을 합산.
- [x] 입력 중 표시는 수신 후 3초 이내 만료. 연결 해제 시 해제.

## Task 3: HTTP 변경 방송 — 완료

- [x] 신규 상담·배정·상태·메시지를 HTTP 성공 후 소켓으로 전파.
- [x] `chatRoomService`는 소켓 서버를 import하지 않고 변경 결과를 반환. 라우터/작업 조정 계층에서 방송.
- [x] 인계 전환은 방 잠금 트랜잭션으로 처리.
- [x] `POST /api/public/chat/:roomId/handoff` 추가. 위젯은 HTTP로 확정 응답을 받고 소켓 연결 여부와 무관하게 waiting 전환.

일반 요청 문장만 전송하던 폴백은 폐기했다. 이미 waiting/active이면 안내 메시지를 추가하지 않는다.

## Task 4: 고객 위젯 — 완료

- [x] `socket.js`와 `stream.js`를 추가해 소켓 우선, 오류/해제 시 REST 폴링으로 전환.
- [x] 입장 완료 전에는 전송을 HTTP로 처리. 초기 연결 오류에도 5초 제한 유지.
- [x] 재연결 시 재입장해 누락 메시지 병합, 성공 시 폴링 중단.
- [x] 이전 세션의 콜백·타이머가 새 상담에 영향을 주지 않도록 세션·연결 소유권 검사.
- [x] 번역 메시지 갱신도 ID로 병합.

위젯은 Socket.IO CDN 클라이언트 4.7.5, 서버/관리자는 lockfile의 4.8.x를 사용한다. Socket.IO 내부 HTTP polling transport와 REST fallback은 서로 다른 경로다. CDN 차단 시 REST로 계속 상담 가능하다.

## Task 5: 관리자 화면 — 완료

- [x] 인증된 앱의 소켓 싱글턴, 로그아웃/401 시 종료.
- [x] 상세 3초·목록 5초 REST 폴링을 안전망으로 유지하면서 이벤트를 즉시 반영.
- [x] join 응답 이후 실시간 연결 표시. 재연결 때 최신 상세 조회.
- [x] 방 이동·화면 해제·숨김 때 leave, 복귀 시 join. 서버도 소켓당 현재 상담방 하나만 유지.
- [x] join/leave를 소켓별 순서대로 처리해 빠른 이동 시 이전 방이 남는 문제 수정.
- [x] 상태 이벤트 이전에 시작한 HTTP 응답 무효화, 목록 조회 중 이벤트가 오면 후속 조회.
- [x] Phase2·3 세대 검사·appendNote·IME·초안 및 스크롤 보존 유지.

## Task 6: 읽음 — 완료

- [x] 운영자가 실제 구독 중인 방으로 전달된 고객 메시지를 읽음 처리.
- [x] `markDeliveredRead`는 동일 방 잠금과 메시지 생성 시각을 사용. 읽음 시각은 역행하지 않으며 이후 메시지를 미리 읽지 않는다.
- [x] 다른 방 이동 뒤 이전 방의 unread가 계속 증가하는지 통합 테스트.

읽음은 방 단위 공유값이며 개인별/메시지별 읽음 확인이 아니다. 소켓에 전달했다는 기준으로, 사람이 실제 문장을 읽었다는 보장은 아니다.

## Task 7: 접속 상태 — 완료

- [x] DB에 접속 플래그를 남기지 않고 현재 소켓에서 계산.
- [x] disconnecting에서 방 목록을 보존하고 퇴장 후 presence 갱신.
- [x] 위젯에 부재/접속/방 참가 표시, 연결 실패 시 오래된 표시 초기화.

`anyOperatorOnline`은 운영자 연결 존재, `operatorOnline`은 해당 방 운영자 구독 존재다. 특정 배정 담당자의 재실·업무 가능 여부를 뜻하지 않는다. 단일 API 프로세스 기준이다.

## 검증 및 다음 단계

실제 Socket.IO 통합 테스트와 고객/관리자 Chromium E2E를 실행했다. 쿠키 혼재에서도 고객 발신 유지, 소켓 차단 시 waiting 전환, 스크롤/재입장/세션 격리 회귀를 포함한다. 전체 검증 수치와 운영 제한은 [Phase6 완료 기록](20260904_phase6_상담채팅시스템개발계획서.md)을 따른다.
