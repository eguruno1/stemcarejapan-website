# Phase 5: 번역 및 AI 상담 — 완료

작성일: 2026-09-04 · 구현 검토 완료일: 2026-09-18

상태: **구현·목업 및 로컬 통합 검증 완료**. 실제 OpenAI API 키를 사용하는 번역 품질·응답 품질·지연 검증은 미실시이며 운영 전 별도 검증이 필요하다. 자동 테스트는 개발 환경에 키가 있어도 외부 API를 호출하지 않는다.

[검토 전 계획서](../history/20260918_phase4-6_review/20260904_phase5_상담채팅시스템개발계획서.md)는 보존한다. 초안과 다른 구현·추가 수정은 아래가 최종 기준이다.

## Task 1: AI 클라이언트 — 완료

- [x] 공용 `callModel`, `setModelCaller` 테스트 주입, `AiUnavailableError` 통합.
- [x] Chat Completions 사용. AI/요약은 JSON mode, 번역은 텍스트.
- [x] 번역 8초, AI/요약 15초 제한. 시간 초과 시 AbortSignal로 실제 SDK 요청도 취소하고 SDK 내부 재시도는 0회로 설정.
- [x] API 키 부재·서비스 오류·빈 응답·형식 오류를 안전하게 처리.

단순 Promise 타임아웃은 외부 요청을 멈추지 않으므로 취소 신호까지 추가했다. 설정된 모델은 변경하지 않았다. [공식 재시도 지침](https://developers.openai.com/api/docs/guides/rate-limits)과 설치된 SDK 요청 옵션을 확인했다.

## Task 2: 언어 감지·번역 — 완료

- [x] 한글/가나/한자 규칙 감지, 감지 불가 시 저장 언어·고객 선호 언어 사용.
- [x] 동일 언어/빈 입력 생략, 모델 오류 시 원문 유지.
- [x] 고객→운영자 번역 대상은 항상 한국어. 원문의 실제 문자 언어를 고객 선호값보다 우선해 잘못된 언어 태그 보완.

일부 기존 배정·종료·명시적 연결 요청 시스템 안내는 한국어 고정 문구이며 이 고객 원문 번역 경로의 대상이 아니다.

한자만 있는 문장을 일본어로 보는 등 휴리스틱의 한계가 있다. 자동 번역의 정확성은 라이브 검증 대상이다.

## Task 3: 고객 메시지 자동 번역 — 완료

- [x] HTTP/소켓으로 원문을 먼저 저장·전달하고 비동기 번역.
- [x] 최초 상담 폼의 고객 문의에도 번역 적용. 고정 인사말 때문에 번역이 누락되던 경로 보완.
- [x] pending/done/failed 상태 및 `chat:message:update` 전파, 원문·고객용 visibleText 보존.
- [x] 동일 메시지 번역 작업 병합. 재번역은 고객 메시지에만 적용하고 운영자가 확정한 done/edited 번역을 덮어쓰지 않음.
- [x] 작업 추적·배수(`drainBackground`)를 추가해 테스트 초기화/서버 종료와 DB 쓰기 경합 방지.

초안의 oppositeLanguage가 아니라 한국 기반 운영자의 읽기 언어인 `ko`를 사용한다. 작업은 메모리 기반이며 서버 중단 후 자동 재실행하는 영속 작업 큐는 이번 범위가 아니다.

## Task 4: 번역 미리보기·수정 후 전송 — 완료

- [x] 운영자 원문 언어 기본값 한국어. 고객 선호 언어와 다르면 미리보기.
- [x] 번역문 수정·다시 번역·취소·확정, 수동 수정은 edited 상태 저장.
- [x] 번역 서비스 실패 시 운영자가 번역문을 직접 작성해 전송 가능.
- [x] clientMessageId 재사용·IME 보호·방별 작성 상태 격리 유지.
- [x] 미리보기 중 상담이 종료되면 재번역·수정·전송을 잠금.

## Task 5: 운영자 전환 규칙 — 완료

- [x] 한일 가격/예약/건강상태/의료 판단/운영자 요청/불만/긴급 패턴.
- [x] 모델 호출 전 규칙 검사, 반복적인 AI 답변에 대한 전환 기준.
- [x] 첫 상담 폼의 민감 문의·운영자 요청도 즉시 waiting으로 전환. 일반 문의에는 고정 인사만 생성.
- [x] 전환 이후 waiting/active/closed에서는 AI가 자동 개입하지 않음.

규칙은 모든 표현을 포괄하는 안전성 보장이 아니다. 의료·가격·예약 응답의 최종 판단은 운영자가 맡으며, 실제 운영 전 한일 표현별 평가가 필요하다.

## Task 6: 상담 봇·요약 — 완료

- [x] 최근 고객/AI 대화 10건을 기준으로 JSON 결정을 검증. 실패 시 운영자 전환.
- [x] 방별 AI 작업을 순서대로 실행. 중복 요청의 신규 저장 여부는 메시지 트랜잭션 안에서 판정.
- [x] 모델 응답 후 동일 방 잠금 안에서 bot 상태와 마지막 메시지 시각을 재확인. 배정·종료·새 메시지 뒤의 낡은 결과 폐기.
- [x] waiting 전환과 시스템 안내 저장을 한 트랜잭션으로 처리. DB commit 후 방송.
- [x] 요약은 최초 20건이 아닌 최근 20건을 시간순으로 사용. 보관 정리로 원본이 삭제됐으면 늦은 요약을 다시 저장하지 않음.

요약 실패는 상담을 중단하지 않는다. AI 판단 이유 전체를 개인정보 포함 가능성이 있는 로그에 출력하지 않는다.

## Task 7: 고정 인사·요약 표시 — 완료

- [x] 한일 고정 인사는 API 키 없이 상담 시작 시 저장.
- [x] 일반 첫 문의는 고정 인사로 접수 안내하고 AI 개별 답변을 추가 생성하지 않음.
- [x] 인계 요약·고객 요구·다음 행동·위험 태그를 관리자 패널에 표시.

## 완료 범위와 검증

목업 모델로 실패·시간 초과 취소·응답 형식·동시 AI 턴·답변 도중 상태 변경·실제 언어와 선호 언어 불일치를 검증했다. 브라우저에서 키 없는 번역 실패 후 수동 번역 전송 흐름도 확인했다. 전체 결과는 [Phase6 검증 기록](20260904_phase6_상담채팅시스템개발계획서.md) 참조.
