## 구현 기준

[Phase 0 공통 제약](20260904_phase0_상담채팅시스템개발계획서.md)을 따른다. UUID 식별자, UTC 저장·ISO 8601 응답, Zod 요청 검증, `{ error: { code, message, details? } }` 오류 형태, bcrypt cost 10 비밀번호, SHA-256 방문자 토큰 해시를 사용한다.

상태 변경은 `chatRoomService`의 배정·상태 변경 함수에서 수행한다. `updateRoomStatus`만 상태를 바꾼다는 초안 설명은 실제 배정 동작에 맞게 정정한다. 방 쓰기는 `roomLock.ts`의 PostgreSQL 행 잠금과 Prisma 트랜잭션으로 보호한다. 현재 REST 라우터에는 인증 후 조회 및 DTO 조립도 일부 있으며, 향후 Socket.IO가 추가될 때도 쓰기는 공용 서비스 함수를 재사용한다.

## Task 6: 고객 상담 API — 완료

- [x] 동의·연락처·언어·서비스 검증 후 상담 시작, 방문자 토큰 1회 반환.
- [x] 고객·상담방·첫 메시지를 **동일 트랜잭션**으로 저장. 첫 메시지 실패 시 전체 롤백.
- [x] 다른 방의 토큰은 403, 토큰 없음은 401.
- [x] 고객 조회·전송, 종료 방 전송 거부, 같은 발신자의 재전송 중복 방지.
- [x] 고객 응답에서 연락처·이메일·운영자 메모와 내부 번역 내용 제외.

`createMessage(input, tx?)`는 기존 트랜잭션을 전달받거나 새 트랜잭션을 연다. 행 잠금 뒤 종료 여부와 중복을 검사하므로 라우터 검사 후 방이 종료되는 경쟁도 차단한다. 다른 발신자의 ID를 재사용하면 `409 MESSAGE_ID_CONFLICT`다. 같은 발신자가 같은 ID를 다시 보내면 최초 저장된 메시지를 반환하며 종료 방에서는 재전송도 409다.

- [x] 직후 도착한 메시지가 안 읽음으로 남도록 저장 시각을 이전 메시지·읽음 시각보다 뒤로 보장.

읽음 기준은 초안과 동일하게 **방 단위 공유**다. `oldest_waiting` 자체는 상태 필터가 아니므로 대기방만 볼 때 `status=waiting`을 함께 지정한다. 목록 페이지네이션 및 운영자별 읽음 상태는 현재 구현하지 않았다.

## Task 8: 배정·상태·답변·메모 — 완료

- [x] 동시 배정은 한 운영자만 성공, 다른 운영자는 `409 ALREADY_ASSIGNED`.
- [x] 같은 운영자의 반복 배정은 참여 메시지를 중복 생성하지 않음.
- [x] 상태 변경과 시스템 메시지 저장을 한 트랜잭션으로 실행.
- [x] 같은 상태 반복 요청은 종료 시각과 메시지를 유지. 재개하면 closedAt 제거.
- [x] 운영자 답변 원문·번역문·고객 표시문 저장. 시스템 메시지 타입은 `system`.
- [x] 메모 trim·길이 검증과 작성자 정보 반환. 고객 응답에는 메모 미포함.

배정은 초안대로 종료된 방을 재개할 수 있다. 로그인한 활성 운영자는 모든 상담을 조회·답변·메모·상태 변경할 수 있으며, 다른 운영자가 담당 중인 방의 **배정**만 충돌 처리한다. 담당자 전용 수정 권한은 이번 검토에서 추가하지 않았다.
