# Phase 2: 고객용 채팅 위젯 개발계획서 — 완료

작성일: 2026-09-04 · 구현 검토 및 완료일: 2026-09-18

상태: **완료 (REST 폴링 범위)**. `feat/consulting-chat-phase2` 구현을 포함하는 `feat/consulting-chat-phase3` 브랜치에서 검토·수정했다. 서버와 연결된 고객 위젯, 상담 시작·전송·세션 복원·오류 복구·한일 문구·스크롤 동작을 현재 소스 기준으로 검증했다.

초안의 상세 코드 예시는 [검토 전 원문](../history/20260918_phase2-3_review/20260904_phase2_상담채팅시스템개발계획서.md)에 보존한다. 아래 완료 내역과 실제 소스가 현재 기준이며, 초안 코드로 수정된 구현을 덮어쓰지 않는다. API 계약은 [API 문서](../../../apps/api/API.md)를 따른다.

## 실제 구현과 초안의 차이

| 항목 | 현재 구현·확정 기준 |
|---|---|
| 루트 페이지 | `/`도 서비스 선택을 포함한 상담 폼을 제공한다. 초안의 “서비스 링크만 제공” 설명을 정정한다. |
| 파일 분리 | config·i18n·state·api·poller·render·widget의 **7개 ES module**. 번들러 없이 HTML의 `type="module"`로 로드한다. |
| 서버 상수 | 브라우저가 CommonJS shared 패키지를 직접 import하지 않으므로 `config.js`의 서비스·상태 목록을 shared와 동일하게 유지한다. |
| 갱신 | 고객 폴링 3초, 숨겨진 탭에서는 주기 조회 중단, 탭 복귀 시 즉시 조회. 네트워크 시간을 포함한 정확한 3초 수신 보장은 아님. |
| 스크롤 | DOM 갱신 전 바닥 100px 이내일 때만 따라간다. 직접 전송·담당자 요청·패널 재열기도 강제 이동하지 않는다. |
| API 주소 | 로컬 기본 4000 / 그 외 동일 출처. 모듈 로드 전 `window.STEMCARE_CHAT_API_URL`을 지정하면 우선 사용한다. |
| 한국여행 스타일 | 기존 페이지가 공통 style.css를 쓰지 않아 chat-widget.css의 standalone 스타일을 추가 사용한다. |
| 담당자 연결 | 현재는 연결 요청 문장을 고객 메시지로 전송한다. 자동 waiting 전환·AI 중단은 Phase 5에서 구현한다. |
| 테스트 | 기존 Playwright 15건에 위젯 Vitest 6건 추가. E2E는 개발 서버·개발 DB 대신 자동 기동 전용 서버와 TEST_DATABASE_URL 사용. |

## Task 1: config·i18n·state — 완료

- [x] API 주소, 폴링 주기, 세션 키 `scj-chat-session`, 스크롤 임계값 분리.
- [x] 한/일 문구, 언어 전환 감지, 서비스별 기본 선택.
- [x] roomId·visitorToken localStorage 저장·복원, 저장 차단 시 메모리 사용.
- [x] 저장된 세션 필드가 문자열인지 확인해 잘못된 저장값을 무시.
- [x] 서버 메시지 병합과 고객 발신 메시지의 clientMessageId로 pending 정리.
- [x] 실패 pending만 재시도하도록 제한해 중복 클릭 방지.

같은 페이지 출처의 세 서비스 페이지는 하나의 상담 세션을 공유한다. 서버 확정 전 pending은 메모리에만 있으며 새로고침 시 실패·미확정 초안을 복원하지 않는다.

## 완료 범위 및 후속 인계

Phase 2의 REST 고객 위젯 범위는 완료했다. Socket.IO는 Phase 4, 자동 언어 감지·번역·AI·담당자 자동 연결 정책은 Phase 5, 공개 배포는 Phase 6 범위다. 기존 Sites 정적 호스팅에 API가 자동 추가되는 것은 아니므로 이 브랜치 검토로 운영 배포 완료를 판정하지 않는다.
