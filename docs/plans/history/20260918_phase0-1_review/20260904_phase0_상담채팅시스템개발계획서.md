> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

작성일: 2026-09-04

**Goal:** 상담채팅시스템 MVP를 얹을 npm workspace 모노레포(정적 홈페이지 + API 서버 + 관리자 화면 + PostgreSQL)를 만들고, 네 개가 동시에 실행되는 상태를 확인한다.

**Architecture:** 기존 정적 홈페이지(`index.html`, `css/`, `js/`, `stemcell/`, `korea-travel/`)는 그대로 두고, 루트에 npm workspace를 추가해 `apps/api`(Express + Socket.IO), `apps/admin`(Next.js), `packages/shared`(공용 타입)를 새로 만든다. PostgreSQL은 Docker Compose로 띄운다. 이 Phase에서는 채팅 기능을 하나도 만들지 않는다. "실행되는 빈 껍데기"까지만 만든다.

**Tech Stack:** Node.js 22 LTS, npm workspaces, TypeScript 5(CommonJS), Express 4, Vitest + Supertest, Next.js 15(App Router), PostgreSQL 16, Docker Compose

**Spec:** `docs/20260904_상담채팅시스템구축방향.md`, `docs/plans/20260904_phase0_상담채팅시스템구축계획서.md`

## Global Constraints (Phase 0~6 전체 공통)

이 항목들은 모든 Phase의 모든 Task에 암묵적으로 포함된다.

- **Node.js 22 LTS** 를 사용한다. (`node -v` 가 `v22.x` 여야 한다)
- **TypeScript는 CommonJS로 컴파일한다.** (`"module": "commonjs"`) — ESM으로 하면 상대경로 import에 `.js` 확장자를 붙여야 해서 초보자가 자주 막힌다.
- 포트 고정: **홈페이지 8080 / 관리자 3100 / API 4000 / PostgreSQL 5434**
- 언어 코드는 `ko`, `ja` 두 가지만 쓴다. 감지 실패는 `unknown`.
- 서비스 코드는 `stemcell`, `korea_travel`, `undecided` 세 가지만 쓴다.
- 상담방 상태는 `bot`, `waiting`, `active`, `closed` 네 가지만 쓴다.
- 발신자 타입은 `customer`, `operator`, `ai`, `system` 네 가지만 쓴다.
- 번역 상태는 `none`, `pending`, `done`, `failed`, `edited` 다섯 가지만 쓴다.
- 위 상수는 **반드시 `packages/shared`에서 import** 한다. 문자열을 직접 타이핑하지 않는다.
- `.env` 파일은 절대 Git에 올리지 않는다. `.env.example` 만 올린다.
- `docs/` 폴더는 현재 `.gitignore`에 등록되어 있어 Git에 올라가지 않는다. 계획 문서는 로컬 문서로 관리한다.
- 모든 Task는 **테스트를 먼저 쓰고(RED) → 구현하고(GREEN) → 커밋** 순서로 진행한다.
- 커밋 메시지는 한 줄 영문 `feat:` / `chore:` / `test:` / `fix:` 접두어를 쓴다.

## 이 Phase를 시작하기 전에 알아야 할 개념

초보 개발자를 위한 최소 설명이다.

**npm workspace(모노레포)란?**
폴더 하나 안에 여러 개의 독립적인 npm 프로젝트를 두고, 루트에서 한 번에 관리하는 방식이다. `npm install`을 루트에서 한 번만 실행하면 `apps/api`와 `apps/admin`의 패키지가 모두 설치된다. 공용 타입(`packages/shared`)을 두 앱이 같이 쓸 수 있다는 게 가장 큰 장점이다.

**왜 API 서버와 관리자 화면을 분리하나?**
API 서버는 "데이터를 저장하고 꺼내주는 곳"이고, 관리자 화면은 "그 데이터를 사람이 보는 곳"이다. 둘을 섞으면 나중에 고객 위젯(정적 HTML)도 같은 API를 써야 할 때 곤란해진다. 지금 분리해두면 고객 위젯 / 관리자 화면 / 미래의 모바일 앱이 모두 같은 API 서버 하나를 바라볼 수 있다.

**왜 PostgreSQL을 Docker로 띄우나?**
내 노트북에 PostgreSQL을 직접 설치하면 버전이 꼬이고 지우기도 어렵다. Docker로 띄우면 `docker compose down -v` 한 줄로 완전히 지우고 다시 만들 수 있다.

        └── lib/
            └── env.ts             ★
```

**파일별 책임**

| 파일 | 책임 |
|---|---|
| `packages/shared/src/constants.ts` | 상태값 문자열 원본. 여기만 고치면 전 프로젝트가 따라온다 |
| `packages/shared/src/types.ts` | API가 주고받는 JSON 모양 정의 |
| `apps/api/src/config.ts` | `process.env` 를 읽는 **유일한** 파일 |
| `apps/api/src/app.ts` | 라우터를 붙인 Express 앱을 만들어 반환. 포트를 열지 않는다 |
| `apps/api/src/server.ts` | `app.ts`가 만든 앱을 실제 포트에 붙인다 |

`app.ts`와 `server.ts`를 나누는 이유가 중요하다. 테스트는 실제 포트를 열지 않고 앱 객체만 있으면 되기 때문이다. 이렇게 나눠두면 Supertest로 빠르게 테스트할 수 있다.

export type Language = (typeof LANGUAGES)[number];

export const DETECTED_LANGUAGES = ['ko', 'ja', 'unknown'] as const;
export type DetectedLanguage = (typeof DETECTED_LANGUAGES)[number];

export const SERVICE_TYPES = ['stemcell', 'korea_travel', 'undecided'] as const;
export type ServiceType = (typeof SERVICE_TYPES)[number];

export const CHAT_ROOM_STATUSES = ['bot', 'waiting', 'active', 'closed'] as const;
export type ChatRoomStatus = (typeof CHAT_ROOM_STATUSES)[number];

export const SENDER_TYPES = ['customer', 'operator', 'ai', 'system'] as const;
export type SenderType = (typeof SENDER_TYPES)[number];

export const MESSAGE_TYPES = ['text', 'image', 'file', 'system'] as const;
export type MessageType = (typeof MESSAGE_TYPES)[number];

export const TRANSLATION_STATUSES = ['none', 'pending', 'done', 'failed', 'edited'] as const;
export type TranslationStatus = (typeof TRANSLATION_STATUSES)[number];

export const OPERATOR_ROLES = ['admin', 'operator'] as const;
export type OperatorRole = (typeof OPERATOR_ROLES)[number];
```

`as const` 를 붙이면 TypeScript가 `string[]`이 아니라 `readonly ['ko','ja']`로 좁혀 인식한다. 그래서 `(typeof LANGUAGES)[number]` 가 `'ko' | 'ja'` 타입이 된다. 상수 목록과 타입을 한 곳에서 동시에 얻는 표준 패턴이다.

- [ ] **Step 1: `docker-compose.yml` 교체**

현재 파일에는 정적 홈페이지용 `web` 서비스만 있다. `postgres`를 추가한다.

```yaml
services:
  web:
    build: .
    ports:
      - "8080:80"
    volumes:
      - ./index.html:/usr/share/nginx/html/index.html
      - ./css:/usr/share/nginx/html/css
      - ./js:/usr/share/nginx/html/js
      - ./images:/usr/share/nginx/html/images
      - ./stemcell:/usr/share/nginx/html/stemcell
      - ./korea-travel:/usr/share/nginx/html/korea-travel

  postgres:
    image: postgres:16
    environment:
      POSTGRES_USER: stemcare
      POSTGRES_PASSWORD: stemcare
      POSTGRES_DB: stemcare_chat
    ports:
      - "5434:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
      - ./docker/postgres-init:/docker-entrypoint-initdb.d
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U stemcare -d stemcare_chat"]
      interval: 5s
      timeout: 3s
      retries: 10

volumes:
  postgres_data:
```

- [ ] **Step 2: 테스트용 DB를 자동 생성하는 초기화 스크립트 작성**

import cors from 'cors';
import express, { type Express, type NextFunction, type Request, type Response } from 'express';
import { config } from './config';

export function createApp(): Express {
  const app = express();

  app.use(
    cors({
      origin: config.corsOrigins,
      credentials: true
    })
  );
  app.use(express.json({ limit: '1mb' }));

  app.get('/health', (_req: Request, res: Response) => {
    res.json({ status: 'ok', service: 'stemcare-chat-api' });
  });

  // 등록된 라우터에 걸리지 않은 모든 요청
  app.use((_req: Request, res: Response) => {
    res.status(404).json({
      error: { code: 'NOT_FOUND', message: '요청한 경로를 찾을 수 없습니다.' }
    });
  });

  // 마지막 안전망: 어디선가 던져진 예외를 표준 형식으로 바꾼다.
  app.use((err: unknown, _req: Request, res: Response, _next: NextFunction) => {
    console.error('[unhandled]', err);
    res.status(500).json({
      error: { code: 'INTERNAL_ERROR', message: '서버 내부 오류가 발생했습니다.' }
    });
  });

  return app;
}

      .catch((err: Error) => setHealth({ kind: 'error', message: err.message }));

  return (

          marginTop: 24
        }}

## 초보자가 자주 막히는 지점

**"npm install 했는데 @stemcare/shared 를 못 찾는다"**
`packages/shared` 를 빌드하지 않아서다. `npm run build -w packages/shared` 를 먼저 실행한다. `package.json`의 `main`이 `dist/index.js`를 가리키므로 `dist`가 없으면 찾지 못한다.

**"docker compose up 했는데 테스트 DB가 없다"**
초기화 SQL은 볼륨이 비어 있을 때만 실행된다. `docker compose down -v` 로 볼륨까지 지우고 다시 올린다. `-v` 를 빼면 데이터가 남아 있어 다시 실행되지 않는다.

**"app.ts 와 server.ts 를 왜 나누나"**
테스트는 실제로 4000번 포트를 열 필요가 없다. `createApp()` 이 반환한 객체만 있으면 Supertest가 가짜 요청을 넣어볼 수 있다. 포트를 여는 코드가 섞여 있으면 테스트를 여러 개 돌릴 때 "포트가 이미 사용 중" 오류가 난다.
